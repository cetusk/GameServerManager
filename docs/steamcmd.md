# SteamCMDの導入と共通パス

SteamCMDはゲームサーバーなどを取得するValveのコマンドラインツールです。通常のSteamクライアントには付属しません。1つのSteamCMDを複数ゲームで共用でき、更新時にはゲームごとのSteam App IDとサーバー設置先を指定します。

## 既定候補

SteamCMDには固定のインストール先がありません。このアプリでは、Windowsでの配置例にある`C:\steamcmd\steamcmd.exe`を既定候補にしています。これはインストール済みであることや書き込み権限を保証する値ではありません。別ドライブやユーザーが書き込めるフォルダーへ変更できます。

参考資料:

- [Valve Developer Community: SteamCMD](https://developer.valvesoftware.com/wiki/SteamCMD) — ツールの案内。
- [ValveのissueにあるWindows / ARK SAでの利用例](https://github.com/ValveSoftware/steam-for-linux/issues/10612) — `C:\SteamCMD\steamcmd.exe`と別のサーバー設置先を指定した例。固定の標準パスを定めた資料ではありません。
- [Facepunch: Downloading a Dedicated Server](https://wiki.facepunch.com/gmod/Downloading_a_Dedicated_Server) — SteamCMDにゲームのApp IDと設置先を指定する手順。
- [ValveのWindows版ZIP配布元](https://steamcdn-a.akamaihd.net/client/installer/steamcmd.zip) — アプリが使用するダウンロードURL。

## アプリ設定での操作

「アプリ設定 → SteamCMD」で実行ファイルの絶対パスを指定します。

- **既存の exe を選ぶ → このパスを保存**：手元の`steamcmd.exe`を使い、共通パスを保存します。既存exeを起動したり置き換えたりはしません。
- **配置フォルダーを選ぶ → ダウンロードして設定**：空の配置先にValve配布ZIPをダウンロード・展開し、成功後に共通パスを保存します。ダウンロードの進捗と結果を画面に表示します。
- **既定候補に戻す**：入力欄を`C:\steamcmd\steamcmd.exe`へ戻します。保存やダウンロードは別のボタンで実行します。

ダウンロード機能はWindowsの実管理モードで利用できます。SteamCMDの起動用exeを配置する機能で、初回の自己更新はゲームサーバーの「更新・インストール」時に行います。ゲームサーバーの更新もインターネット接続が必要です。

「更新・インストール」は、先に`+quit`だけでSteamCMDの初期化・自己更新を確認してから、別の呼び出しでゲームの`+app_update`を実行します。初期化は最大3回まで確認し、同じSteamCMD実行ファイルのプロセスが残っている間は次を起動しません。再起動したプロセスの終了確認には最大10分待機し、確認できない場合は失敗として詳細を表示します。ゲーム更新は正常終了と、その呼び出しのログにある対象App IDの更新成功を両方確認します。過去の成功行や自己更新の完了だけではゲーム更新完了と判定しません。

## 共通パスと個別パスの関係

共通パスは新規サーバー設定の初期値です。5ゲームともSteamCMD欄を残しており、実際の更新にはその欄に保存された個別パスを使用します。共通パスの変更によって既存の設定ファイルを書き換えることはありません。

既存のサーバー設定へ共通パスを取り込む場合は、SteamCMD欄の「既定パスを入力」を押して変更内容を確認・保存します。保存前に通常の設定バックアップを行います。新規作成中の未保存入力も、共通設定を変更しただけでは上書きしません。

保存済みの共通パスは管理データ内の`local-steamcmd.json`に記録します。PC固有のパスなので、表示・通知などのアプリ設定エクスポートには含みません。模擬モードは`mock-steamcmd.json`を分離して読み、実ダウンロード・共通設定保存は行いません。

## 失敗時と同時実行

ゲームサーバーの更新に失敗した場合は、作業履歴にSteamCMDの終了コード、更新ログのフルパス、今回の出力の末尾を表示します。更新ログは管理データの`instances/<サーバーID>/steamcmd.log`です。「ログ」画面でも末尾を確認でき、コピーには操作記録・サーバーログ・SteamCMD更新ログを含みます。過去のログも含まれるため、失敗時の作業履歴と合わせて確認してください。認証情報は従来の規則で伏せます。実行前の失敗ではOSのエラーも表示します。

既存のファイルがあるフォルダーへの導入は拒否します。既存SteamCMDを使う場合は「このパスを保存」を選んでください。取得失敗や不正なZIPを検出した場合、途中のexeを正式な配置先に置いたり、共通パスを変更したりはしません。書き込み権限がない場合は別のフォルダーを選びます。

ZIPはValveの固定HTTPS URLから取得し、サイズ上限・CRC・エントリー名・Windows実行ファイル形式を確認して、一時ファイルから非上書きで配置します。実行ファイル形式の検査は電子署名の検証ではありません。ネットワーク処理には接続15秒・全体120秒のタイムアウトを設けています。

アプリ内の実サーバー操作は順番に処理します。さらに、同じSteamCMDフォルダーの`.gsm-steamcmd.lock`を配置中・サーバー更新中に保持して、このアプリからの同時利用を防ぎます。外部から手動起動したSteamCMDにはこのロックは適用されませんが、更新前のプロセス確認で使用中・状態不明なら更新を開始しません。ゲームサーバー更新時の作業フォルダーにはSteamCMDのフォルダーを指定します。

実際のValve配布ZIPを一時フォルダーへ取得・展開する検証は実施済みです。ユーザー環境ではダウンロードとSteamCMD自己更新のログを確認しています。初期化・ゲーム更新を分離した修正後のWindows実機での一連の確認は未実施です。
