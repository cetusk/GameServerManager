# サーバー設定の GUI 編集

登録済みサーバーを停止し、**サーバー設定 → 設定を編集 → 変更内容を確認 → バックアップして保存** と進めます。設定の保存後は登録情報を更新し、管理画面を自動で開き直します。再登録ボタンを追加で押す必要はありません。ゲームへの適用は次回起動時です。

「設定を編集」を開いた後に別画面へ移動すると、変更の有無にかかわらず離脱確認が出ます。「編集を続ける」で入力を維持し、「変更を破棄して離れる」で指定した画面へ移動します。ワールド設定と新規作成も同様です。

## 5 ゲームの対象項目

| ゲーム | 接続・動作設定 | 保存場所・ツール |
|---|---|---|
| Valheim | サーバー名、接続ポート、参加パスワード、公開範囲、クロスプレイ、自動保存間隔、ゲーム内バックアップ件数 | SteamCMD、設置先、ワールド保存先、バックアップ先、ログ出力先 |
| ARK SA | プロファイル名、サーバー名、接続／検索／RCON ポート、参加／管理者パスワード | SteamCMD、設置先、バックアップ先。ワールドは設置先＋選択マップから決定 |
| Conan Exiles | サーバー名、接続／検索／RCON ポート、RCON 有効化、最大人数、参加／管理者／RCON パスワード | SteamCMD、設置先、バックアップ先。ワールドは `ConanSandbox/Saved` 配下 |
| Windrose | 実際の ServerDescription に存在するサーバー名、参加パスワード、パスワード保護、最大人数 | SteamCMD、設置先、バックアップ先。ワールドは保存プロファイル・バージョン・ID から決定 |
| Satisfactory | 管理画面での表示名、接続／メッセージング／外部メッセージングポート、管理 API のログイン用パスワード／トークン | SteamCMD、設置先、実際の SaveGames の参照先、バックアップ先、読み取るログファイル |

固定・自動決定される保存先は「保存範囲」に表示します。パスは直接入力または「参照…」で選択できます。既存ファイルを選ぶログダイアログのほか、未作成のログ名は直接入力できます。

## 保存先変更の意味

パスの変更は参照先の変更です。既存ワールド、ゲーム本体、過去のバックアップを自動移動しません。保存前の退避には**変更前のバックアップ先**を使います。新しいバックアップ先の重複・危険なパス、他の登録サーバーの設置先・保存先との重複は保存前に検証します。変更後の保存対象パスと一致しないバックアップの復元は従来どおり拒否します。

ARK / Conan / Windrose で設置先とその設置先内のゲーム設定を同時変更する場合は保存を止めます。先に設置先を保存して管理画面を開き直し、その移動先の設定を編集してください。旧設置先のファイルに誤ってパスワードなどを書き込むことを防ぎます。ARK の旧相対設置先はそのまま保持し、GUI で設置先を変更すると絶対パス指定へ切り替えます。

Satisfactory の `save_dir` はゲームの実際の `%LOCALAPPDATA%/FactoryGame/Saved/SaveGames` と一致する必要があります。設定を書くだけで保存場所を移動する機能ではありません。`log_file` は監視対象の指定で、ゲームのログ出力先を変更する機能ではありません。

## ゲーム固有の反映先と制約

- ARK はプロファイルのポート・参加パスワードと有効な起動コマンドを同時更新します。RCON ポート・管理者パスワードは `GameUserSettings.ini` にも反映します。RCON は正常停止に必要なので無効化しません。カスタム起動コマンド使用時は有効な override 側を更新し、追加引数と MOD 順序を保持します。
- Conan のサーバー名は `Engine.ini` の `[OnlineSubsystem] ServerName`、参加・管理者パスワードは `ServerSettings.ini`、RCON パスワードは `Game.ini` の `[RconPlugin] RconPassword` に保存します。既存設定の編集では、ファイルが未生成の項目は理由を表示します。下記の明示的な新規作成では必要な INI を生成します。
- Windrose の旧ツールでも接続ポートは指定していません。旧ソースの ServerDescription キー名には未確認のものがあるため、実ファイル内で一意に存在するキーだけを編集します。ネストされたキーは同じ位置へ書き戻し、トップレベルへ別のキーを追加しません。未存在・重複キーは編集不可と表示します。ワールド ID と招待コードは変更しません。
- Satisfactory の API 欄は**設定済みの認証情報をこの管理ツールに教えるための欄**です。実サーバーの参加／管理者パスワード変更、サーバー名変更、claim、初期セッション作成はゲーム内の Server Manager で行います。参加パスワードを編集できたように見せる無効な入力欄は設けません。
- パスワード／トークンは現在値を表示せず、空欄なら維持します。変更値はマスク入力し、確認・履歴にも内容を表示しません。このフォームでは空文字への削除は行いません。
- Valheim のワールドパラメーター編集は従来どおりです。その他の詳細ワールド設定・MOD 設定などは元ファイル編集を使います。旧ツールの全設定項目の移植完了を意味しません。

## スレッドと保存保護

設定読込・複数ファイルの確認・保存前の検証・保存処理はワーカーで実行します。GUI スレッドでは下書きと表示モデルだけを更新します。設定検証中は入力を無効にし、確認対象が変わることを防ぎます。言語切替・ポーリングで入力モデルを作り直しません。

保存は既存の操作排他、停止確認、バックアップを通ります。各ファイルを読込時のハッシュと照合し、許可された編集先かつバックアップ範囲内であることを確認します。変更前の内容を回復記録に同期してから、一時ファイルで置換し、登録元ファイルは最後に保存します。途中失敗時は元の内容へ戻します。外部変更があり自動回復できない場合は上書きせず「回復」が必要な状態で停止します。

中断時の `instances/<ID>/settings-undo.json` は元設定と変更後設定を含むため、バックアップと同様に認証情報を含みます。成功・回復後に削除し、アプリ設定のエクスポートには含めません。再起動時は記録中の元設定のハッシュを登録情報と照合し、その元の構成で回復対象を解決します。回復記録を手作業で削除して起動しないでください。

## 確認の区別

人工データで各ゲームの項目変換・起動引数、秘密の非表示、未知項目保持、対象外ファイル拒否、外部変更検出、途中保存の回復をテストしています。Windows 実機で今回の新しい設定を保存して各ゲームに適用する試験は未実施です。

## 新しいサーバーの設定を作成

旧管理ツールの設定ファイルがなくても、**サーバー設定 → 新規作成 → 必要事項を入力 → 作成内容を確認 → 作成して登録** と進めます。登録後の反映は自動です。設定ファイルだけを作成し、ゲーム本体のダウンロードや起動は行いません。その後「サーバー操作 → 更新・インストール」を実行し、完了後に管理画面を再読み込みして起動します。

- SteamCMD は「アプリ設定 → SteamCMD」でダウンロード・共通パス設定ができます。新規作成時には共通パス（未保存なら `C:\steamcmd\steamcmd.exe`）を初期入力し、各ゲームの欄で個別変更できます。既存の値は共通設定の変更では上書きせず、「既定パスを入力」を押した場合に取り込みます。実際の更新では各ゲームの欄のパスを使います。詳細は [SteamCMD](steamcmd.md)。
- サーバー設置先は新しい空のフォルダーを指定します。Valheim / Satisfactory のワールド保存先も空である必要があります。既存のゲーム本体やワールドを利用する場合は設定ファイルの登録を使います。
- 管理設定ファイル（ARK は INI、他は TOML）はサーバー設置先の外の新しいファイル名を指定します。既存ファイルは上書きせず、他の登録サーバーとの保存先重複も検証します。登録済みのゲームでは新規作成を表示しません。
- 秘密は初期値を埋めず、必要なゲームでは入力を必須にします。作成確認でも値を表示しません。

| ゲーム | 作成する設定と初回手順 |
|---|---|
| Valheim | 管理 TOML。新しいワールド名と参加パスワードを指定し、起動時にゲームがワールドを生成します。 |
| ARK SA | プロファイル INI と GameUserSettings.ini。マップと正常停止用の管理者パスワードを指定します。RCON を有効にします。 |
| Conan Exiles | 管理 TOML と Engine.ini / ServerSettings.ini / Game.ini。接続・RCON 設定を各ファイルへ保存します。 |
| Windrose | 初回起動用の管理 TOML。ServerDescription やワールド ID はゲーム自身が生成します。初回起動後に停止して管理画面を再読み込みすると、生成済みの情報から通常管理へ移行します。初回設定では SaveProfiles 全体を保存対象にします。既存データを検出したまま初回起動を繰り返すことは拒否します。 |
| Satisfactory | 初回起動用の管理 TOML。保存先は実際の `%LOCALAPPDATA%/FactoryGame/Saved/SaveGames` に合わせます。ゲーム内の Server Manager で claim・名前・パスワード・セッションを設定します。最初はコンソール正常停止を使い、管理 API の認証情報をサーバー設定に登録すると HTTPS の正常停止へ切り替わります。 |

新規作成の検証と書込みはワーカーで実行します。作成直前にも設置先・登録先を再検証します。通常の作成失敗では、この処理が作った未変更のファイルと空のディレクトリーだけを戻します。作成後に登録が失敗した場合は設定ファイルを残し、表示されたパスを「設定ファイルの登録」で登録できます。アプリ強制終了や電源断で中断した複数ファイルの新規作成には永続的な自動回復機構がなく、一部ファイルが残る場合があります。

人工データで5ゲームの新規設定生成・秘密の非表示・既存データ拒否、Conan のファイル作成から登録、Windrose の初回設定から生成済みワールドへの移行を確認しています。新規作成からの Windows 実ゲームのインストール・起動、特に Satisfactory 初期設定段階のコンソール正常停止は実機未確認です。
