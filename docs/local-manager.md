# サーバー管理の使い方

Windows 上の同じ PC にある ARK SA / Valheim / Windrose / Satisfactory / Conan Exiles のサーバーを、1 つの GUI から管理します。ダークテーマ・アイコン付きのゲーム選択画面を維持しています。

## 起動と登録

ソースからは `./run-manager.ps1`、配布フォルダーでは `./start-manager.ps1` を PowerShell で実行します。ソース版は Rust と Visual Studio C++ Build Tools が必要です。`run-dev.ps1` は引き続き模擬モードです。

新しいサーバーは「サーバー設定 → 新規作成」から設定を作成できます。[新規作成の条件と初回手順](server-settings.md#新しいサーバーの設定を作成) を参照してください。未登録の場合は初期設定の案内を表示します。既存サーバーの登録は次の手順です。

1. 使用するゲームを選び、そのゲームの「サーバー設定」を開きます。
2. 「参照…」から旧管理ツールの設定ファイルを選びます。ARK は `Profile/*.ini`、他の 4 ゲームは `config.toml` です。選んだファイルの絶対パスが入力欄に入ります。直接入力も可能で、ダイアログをキャンセルすると元の入力を維持します。
3. 「設定を読み込んで確認」で実行ファイル・ワールド・保存範囲・バックアップ先を確認し、「登録して反映」を押します。
4. 登録成功後に GUI が自動で開き直され、登録が反映されます。起動中のサーバーは終了せず、記録した PID・作成時刻・実行パスを再照合します。
5. 表示が「停止中」になった対象を起動します。既に旧ツールなどで起動しているプロセスは「状態不明」として操作を止めます。旧ツールで正常停止してから切り替えてください。

旧管理ツールを再展開したり、旧 `state.toml` の PID を採用したり、保存先を自動移動することはありません。設定ファイルは UTF-8 が必要です。各ゲーム 1 登録で、元のプロファイルは削除しません。

管理データはソース版では `.manager-data/`、配布版では `data/` に保存します。`-DataDir 'D:\GSM\data'` で変更できます。以前の模擬版に登録した設定は、自動で実管理モードへ移しません。

配色・言語・通知・前回の記憶・設定の移行は [採用 UI の操作説明](native-ui.md) を参照してください。

## 共通操作

サーバー名の下にはワールド・稼働状態と、選択中サーバーの作業状態を表示します。回転アイコンは実行中、チェックは直前の作業の完了、× は失敗です。終了後は「現在処理中の作業はありません」と直前の結果を表示します。設定の検証・登録もこの欄に表示します。全体の作業履歴にはサーバー操作ごとのアイコン・処理名・開始日時・失敗の詳細を表示します。

上部のタブはページの切り替え専用です。操作ボタンは各タブの中に配置しています。

| タブ | 内容・操作 |
|---|---|
| サーバー操作 | 起動・停止、サーバーファイルの更新・インストール |
| サーバー設定 | 設定ファイルの内容確認・登録、5 ゲームの基本設定・保存場所の GUI 編集、詳細な元ファイル編集 |
| ワールド設定 | Valheim のワールドパラメーター編集、他ゲームの編集案内 |
| バックアップ | 「バックアップを作成」、一覧からの復元、未完了処理の回復 |
| ログ | サーバーログの閲覧・全文コピー |

| 操作 | 動作 |
|---|---|
| 起動 | 設定の変更有無、停止、ポートを確認。現在の保存対象を退避してから実行ファイルを直接起動 |
| 停止 | PID・作成時刻・実行ファイルを照合して正常停止を要求。タイムアウト時は失敗を表示し、勝手に強制終了しない |
| バックアップ | 停止中に実ファイルをコピー。コピー前後とコピー先の SHA-256 を照合 |
| 復元 | 対象・内容を検証し、現在のデータを退避してから置換。古い余分なファイルも残さず置換 |
| 更新・インストール | 指定した既存の steamcmd.exe で anonymous / app_update / validate。既存の保存対象を先に退避 |
| 回復 | 停止を確認して、未完了の復元を戻す、または完了済みの一時退避を整理。古いプロセス記録も解除 |
| 元の設定をバックアップして編集 | 停止中に退避し、登録設定と対象のゲーム設定をメモ帳で開く。未知項目・コメントを自動変換しない |

5 ゲームの基本設定は GUI 内で編集・差分確認後、バックアップして保存できます。項目と制約は [サーバー設定の GUI 編集](server-settings.md) を参照してください。詳細な元ファイル編集を使う場合は保存してメモ帳を閉じてから「設定を読み込んで確認」→「登録して反映」と進めます。Windows 11 のメモ帳が別ウィンドウ／既存プロセスへ引き継ぐ場合も、エディターを閉じてから反映してください。更新・復元後にも設定を確認し、「サーバー操作」の「管理画面を再読み込み」で再読み込みしてから起動します。

実操作はアプリ全体で 1 件ずつ処理します。複数ゲームの同時稼働はポートと保存先が分離されている場合に限ります。ゲーム選択の解除や GUI の終了ではサーバーを自動停止しません。ジョブ実行中は GUI を閉じられません。

「稼働中」はプロセスの存在を示します。ログの過去の行だけでゲームへの接続可能を判定しません。サーバーログはファイル末尾の記録なので、停止後や新しい起動が失敗した際にも前回の起動・停止ログが表示されます。全体の操作履歴は今回の GUI 起動中の記録です。バックアップ履歴とプロセス識別記録は次回起動へ引き継ぎます。

## ゲーム別の取り込み条件

### Valheim

旧 `config.toml` の paths / server / manager を使用します。旧パーサ、modifier、preset、world key、crossplay、保存間隔を引き継ぎます。

保護対象は選択ワールドのフォルダー全体、`.db/.fwl/.db.old/.fwl.old`、管理設定、adminlist / bannedlist / permittedlist です。旧 `.db/.fwl` が片方だけ、空ファイル、新形式で同世代の `db2/fwl2/chunks/ok` が揃わない場合はバックアップ・起動を止めます。ファイル構成の検査はゲームがロードできることの保証ではありません。

### Satisfactory

旧 TOML の `paths.save_dir` が、実行する Windows ユーザーの `%LOCALAPPDATA%\FactoryGame\Saved\SaveGames` と同じ実体を指す必要があります。既存のジャンクションを読み取りで照合し、作成・移動・張替えは行いません。`save_dir` 自体にはジャンクションのリンク側ではなく、実体側の絶対パスを指定します。個人の Steam ID フォルダーなどが混在する領域は復元対象にしません。

停止には `manager.api_token` または `server.admin_password` を使用します。新規サーバーの claim と初回セッション作成はゲームのサーバーマネージャーから行ってください。TOML のサーバー名などは表示に使用しますが、ゲーム内設定の変更を HTTPS API へ自動送信しません。

実行ファイルが複数検出された場合は、TOML に実プロセスの絶対パスを追記します。

```toml
[integration]
executable = 'D:\Servers\Satisfactory\FactoryGame\Binaries\Win64\FactoryServer-Win64-Shipping-Cmd.exe'
```

配置には build 差があるため、実在する Shipping / Shipping-Cmd を選びます。`FactoryServer.exe` ランチャーは登録対象にしません。保護対象は専用サーバーの SaveGames 全体と管理設定です。

### Windrose

`R5/ServerDescription.json` を優先候補とし、他の旧配置を含めて 1 ファイルだけ存在することを確認します。専用サーバーで確認されている `save_profile = "Default"` を使用します。

`ServerDescription.WorldIslandId`、フォルダー名、`WorldDescription.WorldDescription.islandId` を照合します。該当ワールドのバージョンが複数ある、または初回で未生成の場合は、旧 TOML に対象 build のバージョンを明示します。

```toml
[integration]
save_version = '0.10.0' # 実際の対象バージョンに変更
```

保護対象は選択ワールドの live フォルダー、`RocksDB_v2_Backups/Worlds/<ID>` のゲーム ZIP、ServerDescription、管理設定です。復元では live と ZIP をまとめて戻します。設定編集では WorldDescription も開きます。文字列化された GameplayTag キーや未知の JSON 項目を自動変換しません。ゲーム更新で保存バージョンが変わった場合は、旧ツールの情報と実際の配置を確認して登録を更新してください。同じワールドが別の version / RocksDB にも残っている場合は、ファイル操作を止めます。使用版を確認し、旧版を別の場所へ退避してから再登録してください。

### Conan Exiles

旧 TOML を参照し、Shipping（なければ Test）実行ファイルを使います。正常停止は Console helper です。

保護対象は `game.db` と `-wal/-shm/-journal`、`Saved/Config/WindowsServer` 全体、`Mods/modlist.txt`、管理設定です。SQLite の検査は一時コピーに対して実施し、元 DB を検査目的で開きません。MOD の順序は modlist の原文を保ちます。ダウンロード済み `.pak` 本体やゲーム側の古い世代 DB はこのバックアップに含みません。

追加起動引数は `-useallavailablecores` / `-nosteam` / `-NoBattlEye` を受け付けます。未対応の引数を黙って無視せず検証で止めます。

### ARK SA

旧 `Profile/*.ini` のマップ・コマンド行・ポートを照合します。相対インストール先は `Profile` の親を基準に解決し、現在の作業フォルダーは使いません。

統合側の出力先を明示するため、プロファイルに次を追加してください。

```ini
[Integration]
BackupDir=D:\GSM-Backups\ARK
SteamCMD=D:\SteamCMD\steamcmd.exe
```

正常停止は RCON の `SaveWorld` → `DoExit` です。プロファイルと `GameUserSettings.ini` の RCON 有効・ポート・管理者パスワードを一致させます。これらを起動 URL に入れないでください。MOD の並び順は起動行のまま引き継ぎます。未検証の追加フラグ・保存先を変えるフラグは検証で止めます。

保護対象は選択マップの `SavedArks/<Map>` 全体、WindowsServer の設定、登録プロファイルです。クラスターの共有保存先や他マップは含みません。

## バックアップの場所と失敗時の扱い

バックアップ先はゲームの設置先、保存対象、管理データの外側に明示します。統合版の形式は `<backup_dir>/gsm/<instance UUID>/<backup UUID>/` の manifest とファイル群です。バックアップ作成時と保存対象のパスが変わっている場合は、復元を拒否します。旧版の ZIP は自動インポート・削除しません。設定を含むバックアップには、元設定に記載された認証情報も含まれます。

管理登録ファイルにはパスと SHA-256、ID のみを保存します。同じ設定パスの停止中の再登録は ID を維持します。プロセス記録が残る設定の変更は拒否するので、正常停止または停止確認後の「回復」を先に行います。別設定パスへの変更は別 ID になります。サーバー稼働中に設定を外部で変更したまま GUI を再起動した場合は、起動時の設定に戻してから再読み込みしてください。変更後のポートを使って別プロセスへ停止要求を送らないための制限です。

復元途中で異常終了した場合は、同じ設定・data-dir で再起動し、停止状態で「回復」を実行します。回復できない状態はエラーとして残し、起動・新たな復元は進めません。バックアップ manifest の破損は一覧にエラーを表示しますが、既に識別できているサーバーの正常停止を妨げません。

## 今回の範囲と実機確認

5 ゲームの基本的な実操作を接続した開発版です。元ツールの全機能を移植した完成版とは区別します。旧 ZIP の形式変換、同一ゲームの複数登録、オンライン backup、定期実行・自動再起動、高度なワールド設定の専用フォーム／プリセット、MOD の取得、Satisfactory の詳細 API 設定は未移行です。

確認済みの動作と未確認の範囲は [対応状況と制約](compatibility.md) を参照してください。

## 管理データの保存先

配布されたexeは直接起動できます。初回に保存先を選び、以後は同じ場所を使います。「アプリ設定 → 保存先」で変更できますが、変更は既存データの移動ではなく別の管理フォルダーへの切り替えです。既存の登録を継続する場合は、従来の管理フォルダー（開発用起動なら`.manager-data`）を選んでください。新しい空フォルダーを選んだ場合はゲーム選択・サーバー登録から始まります。ゲーム本体・ワールド・バックアップのパスは「サーバー設定」で別途指定します。

保存先を切り替える前にすべてのサーバーを停止してください。実行中・状態不明・未完了操作の記録がある場合は切り替えを拒否します。確認エラー時は元の保存先で停止・回復を済ませてください。Windowsでの記憶ファイルは`%LOCALAPPDATA%/GameServerManager/data-location.json`です。起動時の`--data-dir`指定は記憶より優先されます。
